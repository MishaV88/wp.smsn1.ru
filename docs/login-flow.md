# Как работает вход

Документ описывает все способы входа, хранение данных и лимиты. Актуален для версии 1.8.0.

## Компоненты

| Файл | Ответственность |
|---|---|
| `wp-smsn1-ru.php` | шорткоды, AJAX-обработчики, создание пользователя, режим входа, редиректы |
| `includes/wp-smsn1-ru-otp.php` | коды: генерация, транзиенты, лимиты попыток и отправки |
| `includes/wp-smsn1-ru-functions.php` | клиент API smsn1.ru (HTTPS, подпись, баланс, отправители) |
| `includes/wp-smsn1-ru-oauth.php` | VK/Telegram: старт, callback, вход, привязка, кнопки |
| `includes/auth/*` | интерфейсы провайдеров, VK (OAuth 2.1), Telegram (виджет), PKCE |
| `templates/*.php` | формы, переопределяются в теме |
| `assets/js/script.js` | AJAX, таймер, уведомления, подсказка про Telegram |

## Режимы входа

Опция `wp_smsn1_ru_auth_mode`:

- `otp` — только код из СМС;
- `password_otp` — пароль + код (2FA). Пароль проверяется до расхода кода.

## Вход по СМС

```
форма → AJAX send_sms_code → проверки и лимиты → СМС → AJAX verify_sms_code → сессия
```

1. **Отправка.** JS вызывает `admin-ajax.php?action=send_sms_code` с nonce.
   Сервер нормализует номер (10 цифр → `+7XXXXXXXXXX`, иначе `not_russian_num`),
   в форме входа проверяет, что номер зарегистрирован, затем лимиты:
   пауза 60 с, 3 кода на номер и 10 на IP за 20 минут.
2. **Код.** Генерируются 5 цифр, СМС уходит через HTTPS-API. Только после успешной отправки
   создаётся транзиент `wp_smsn1_ru_code_<md5(phone)>`: код, счётчик попыток, время истечения (90 с).
3. **Проверка.** `verify_sms_code`: при 2FA — пароль (5 попыток за 15 минут), затем код
   (`hash_equals`, 5 попыток, после лимита код удаляется).
4. **Сессия.** `wp_set_current_user()`, `wp_set_auth_cookie()`, `do_action('wp_login')`,
   редирект по настройке (поддерживается и slug, и абсолютный URL).

Новый пользователь создаётся как `user_<цифры номера>`, телефон пишется в `billing_phone`.

## Регистрация

Та же форма + e-mail (и пароль в режиме 2FA). E-mail проверяется до расхода кода.
Если e-mail занят — отказ; если номер уже есть — обычный вход.

## VK ID

```
кнопка → /?wp_smsn1_ru_oauth=vk → id.vk.ru/authorize → /wp-smsn1-ru-oauth/?code=… → сессия
```

1. Старт: `state` (32 символа) и PKCE `code_verifier`; транзиент на 10 минут хранит провайдера,
   verifier, `redirect_to` и режим привязки.
2. Редирект на `id.vk.ru/authorize` с `client_id`, `redirect_uri`, `state`,
   `code_challenge` (S256) и `scope` из настроек.
3. VK возвращает `code`, `device_id` и `state` на чистый путь `/wp-smsn1-ru-oauth/`
   (VK не принимает query-параметры в redirect URL).
4. Сервер проверяет `state` (одноразово), меняет код на токен (`POST /oauth2/auth`),
   забирает профиль (`/oauth2/user_info`).
5. Поиск аккаунта по мете `_wp_smsn1_ru_vk_id`:
   - найден — вход;
   - e-mail занят — предложение войти в существующий аккаунт;
   - телефон занят (`billing_phone`) — то же;
   - иначе создаётся `vk_<id>` с e-mail, именем и телефоном из VK.
6. `wp_smsn1_ru_oauth_apply_profile()` переносит телефон в `billing_phone` и e-mail в аккаунт,
   если там пусто и значение не занято другим пользователем.

Привязка: из личного кабинета или профиля админки (`link=1`), только для авторизованного
пользователя; после привязки возврат в кабинет и уведомление.

## Telegram

```
виджет → t.me → /wp-smsn1-ru-oauth/telegram/?id=…&hash=… → сессия
```

1. Виджет рендерится скриптом Telegram (нужен `/setdomain` в @BotFather).
2. Telegram возвращает `id`, имя, `auth_date`, `hash`.
3. Проверка: `secret = SHA256(bot_token)`, `HMAC-SHA256(data_check_string, secret)`,
   `hash_equals`, `auth_date` не старше 15 минут.
4. Поиск по `_wp_smsn1_ru_telegram_id`; если нет — создаётся аккаунт без телефона и e-mail
   (Telegram их не передаёт), в профиле показывается подсказка добавить e-mail.

Привязка: виджет в личном кабинете получает одноразовый токен (10 минут) в `auth-url`:
`/wp-smsn1-ru-oauth/telegram/link/<token>/`. Токен привязан к `user_id` и провайдеру,
принимается только в том аккаунте, из которого открыт.

## Где что хранится

| Данные | Место |
|---|---|
| Телефон | `user_meta.billing_phone` (`+7XXXXXXXXXX`) |
| VK ID | `user_meta._wp_smsn1_ru_vk_id` |
| Telegram ID | `user_meta._wp_smsn1_ru_telegram_id` |
| Телефон из VK | `user_meta._wp_smsn1_ru_vk_phone` |
| Признак «знает пароль» | `user_meta.wp_smsn1_ru_password_set` |
| Код подтверждения | транзиент `wp_smsn1_ru_code_<md5(phone)>` |
| `state` OAuth | транзиент `wp_smsn1_ru_oauth_<state>` |
| Токен привязки | транзиент `wp_smsn1_ru_link_<token>` |
| Счётчики лимитов | транзиенты `wp_smsn1_ru_send_*` |

## Лимиты

| Что | Значение | Фильтр |
|---|---|---|
| Срок жизни кода | 90 с | `WP_SMSN1_RU_OTP_TTL` (константа) |
| Попытки на код | 5 | `wp_smsn1_ru_otp_max_attempts` |
| Пауза между отправками | 60 с | `wp_smsn1_ru_send_cooldown` |
| Кодов на номер | 3 за 20 минут | `wp_smsn1_ru_send_limit_phone` |
| Кодов на IP | 10 за 20 минут | `wp_smsn1_ru_send_limit_ip` |
| Окно лимитов | 20 минут | `wp_smsn1_ru_send_window` |
| Попытки пароля | 5 за 15 минут | — |
| Свежесть Telegram | 15 минут | `wp_smsn1_ru_telegram_max_age` |

## Особенности

1. **Баланс — условие показа формы СМС.** При балансе < 10 ₽ или сбое API форма заменяется
   экраном с входом по логину/паролю и соцкнопками; `wp-login.php` при этом не редиректится.
2. **2FA работает только на форме плагина.** `wp-login.php` пускает по одному паролю,
   если не включён редирект на форму.
3. **Автомержа аккаунтов нет.** Совпадение e-mail или телефона не объединяет аккаунты —
   только явная привязка.
4. **Telegram в РФ.** Домены Telegram у части провайдеров блокируются, поэтому вход
   работает у аудитории вне РФ или с VPN.
