# Альтернативные способы входа: Telegram и VK ID

Статус: проект решения. MAX отложен, но закладывается в ту же абстракцию.

## Зачем

Сейчас единственный способ входа — номер телефона + OTP из СМС, и он работает только для
номеров РФ (провайдер smsn1.ru). Это отсекает:

- пользователей вне РФ (нет доставки СМС, нет +7);
- пользователей, которым дорого/неудобно ждать СМС;
- сценарии, где телефон недоступен (корпоративные аккаунты, смена номера).

Telegram Login и VK ID закрывают эти сценарии, но с разной аудиторией:
**VK ID — основной для РФ**, **Telegram — для аудитории вне РФ** (у части пользователей в РФ
виджет `oauth.telegram.org` недоступен без VPN, поэтому он не должен быть единственным путём входа).

## Архитектура: провайдер как объект

Ввести контракт и реестр. Ядро (авторизация, связывание аккаунтов, редиректы) не должно
знать деталей конкретного OAuth.

```php
interface WP_SMSN1_RU_Auth_Provider {
    public function get_id(): string;            // 'telegram' | 'vk' | 'max'
    public function get_label(): string;         // для кнопки на форме
    public function is_enabled(): bool;          // настройка + наличие ключей
    public function get_authorize_url(string $state, string $code_verifier = ''): string;
    public function handle_callback(array $request): array|WP_Error; // ['provider_uid' => ..., 'email' => ..., 'name' => ...]
}
```

- `includes/auth/class-auth-provider.php` — интерфейс и реестр (`register()`, `get()`, `enabled()`).
- `includes/auth/class-telegram-provider.php`, `class-vk-provider.php`, позже `class-max-provider.php`.
- Точка входа callback — `admin-post.php` (`admin_post_wp_smsn1_ru_oauth_callback`,
  `admin_post_nopriv_...`), не `admin-ajax.php`: нужен redirect, а не JSON.
- Настройки — отдельная секция «Способы входа» на существующей странице плагина.
- Кнопки — в шаблонах `templates/login-form.php`, `register-form.php`, `reg-login-form.php`
  (и в шаблоне темы, если он переопределён). Хук `wp_smsn1_ru_login_buttons` для кастомных тем.

## Поток OAuth (общий)

1. Пользователь жмёт «Войти через …» → `GET /?wp_smsn1_ru_oauth=telegram`.
2. Плагин генерирует `state` (32 байта `random_bytes`), кладёт transient
   `wp_smsn1_ru_oauth_state_<hash>` с TTL 10 минут: `{provider, redirect_to, created_at, code_verifier}`.
3. Редирект на `authorize` провайдера.
4. Провайдер возвращает `code` + `state` на `admin-post.php?action=wp_smsn1_ru_oauth_callback`.
5. Проверка `state` (существует, не истёк, провайдер совпадает) → одноразовое удаление.
6. Обмен `code` на профиль (PKCE, если поддерживается).
7. Поиск пользователя по мета-полю провайдера (`_wp_smsn1_ru_telegram_id` / `_wp_smsn1_ru_vk_id`):
   - найден → `wp_set_auth_cookie` + `do_action('wp_login', ...)`;
   - не найден, но пользователь уже авторизован → предложить «привязать» к текущему аккаунту
     (явное действие с nonce, без автомержа);
   - не найден, гость → создать пользователя (см. «Создание аккаунта»).
8. `wp_safe_redirect` на `redirect_to` (только локальный URL, иначе — на страницу аккаунта).

Требования: `state` хранится на сервере (не в cookie), callback идемпотентен, все ошибки —
через `wp_die` с понятным текстом и логированием, без вывода токенов.

## Telegram Login

- Тип: Login Widget (`<script async src="https://telegram.org/js/telegram-widget.js">`,
  `data-telegram-login`, `data-auth-url` или `data-onauth`).
- Привязка домена: у бота через `@BotFather` → `/setdomain` (иначе виджет вернёт ошибку).
- Проверка подписи: `secret = SHA256(bot_token)`, `hash = HMAC_SHA256(data_check_string, secret)`,
  сравнение `hash_equals`. `data_check_string` — все поля кроме `hash`, отсортированные по ключу,
  `key=value` через `\n`.
- Свежесть: `auth_date` не старше 5 минут (иначе — «ссылка устарела»).
- `id` (Telegram user id) — стабильный идентификатор; `username` может меняться, не использовать как ключ.
- Ограничения: виджет требует доступности `telegram.org`; для аудитории РФ — только как
  дополнительный способ, с подсказкой «если не открывается — войдите по СМС или через VK ID».

## VK ID

- Протокол: OAuth 2.1 + PKCE (VK ID, «Веб»-приложение), authorization endpoint
  `https://id.vk.com/authorize`, обмен кода — `https://id.vk.com/oauth2/auth`.
- Обязательны `client_id`, `redirect_uri` (точное совпадение, https), `code_challenge` (S256),
  `state`; `scope` — минимально необходимый (`vkid.personal_info`, при необходимости `email`).
- Профиль: `https://api.vk.com/method/users.get?user_ids=...&fields=...&v=5.199` с access token,
  либо данные из ответа `id.vk.com` (user_id, first_name, last_name, email при наличии согласия).
- Ключ пользователя — `user_id` VK (числовой), не e-mail.
- Тестовая среда: отдельное приложение VK ID + тестовые аккаунты; боевые ключи — только в настройках
  сайта, не в репозитории.

## Создание аккаунта

`wp_create_user()` требует уникальный логин и e-mail. Для входа через соцсеть e-mail может
отсутствовать (VK отдаёт его только при согласии, Telegram — никогда).

Варианты (нужно решение):
- **A. Требовать e-mail** после первого входа соцсети — форма «подтвердите e-mail», аккаунт
  создаётся только после валидации. Чисто, но добавляет шаг.
- **B. Создавать аккаунт без e-mail** (`user_<provider>_<uid>`), с баннером «добавьте e-mail,
  чтобы восстановить доступ». Быстро, но усложняет восстановление пароля и интеграции,
  ожидающие e-mail (WooCommerce, рассылки).
- **C. Гибрид**: B + напоминание, A — для магазинов (настройка «требовать e-mail»).

Рекомендация: **C**, по умолчанию B для блогов и A для WooCommerce-сайтов.

## Связывание аккаунтов (важно для безопасности)

- Автомерж по e-mail запрещён, если e-mail не подтверждён провайдером (VK может вернуть
  неподтверждённый адрес).
- Привязка соцсети к существующему аккаунту — только из авторизованной сессии, с nonce
  и повторным вводом пароля/OTP.
- Один аккаунт WP ↔ один провайдер = одна запись; отвязка — через профиль, с предупреждением,
  если это единственный способ входа.
- Логировать привязки/отвязки в отдельную таблицу или `user_meta` с датой и IP (для аудита).

## Безопасность: чек-лист

- [ ] `state` на сервере, TTL ≤ 10 минут, одноразовый.
- [ ] PKCE S256 для VK ID; `code_verifier` хранится вместе со `state`, не в URL.
- [ ] `redirect_uri` — белый список, только https.
- [ ] Проверка подписи Telegram через `hash_equals`, `auth_date` ≤ 5 минут.
- [ ] Никаких токенов в логах, URL и `Referer`; обмен кода — на сервере.
- [ ] Rate limit на callback и на создание аккаунтов по IP/провайдеру.
- [ ] `wp_safe_redirect` для `redirect_to`, блокировка open redirect.
- [ ] `do_action('wp_login', $user_login, $user)` после входа (совместимость с 2FA, WooCommerce).
- [ ] Не доверять телефону от провайдера как «подтверждённому» без отдельной верификации.

## Этапы

1. Абстракция провайдеров + настройки + кнопки (без реальных провайдеров — заглушка).
2. VK ID (основной для РФ): OAuth 2.1 + PKCE, вход и привязка.
3. Telegram Login (для аудитории вне РФ).
4. MAX — после появления стабильного API; интерфейс уже готов.
