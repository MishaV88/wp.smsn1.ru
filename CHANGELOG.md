- Заголовок «Войти другим способом» выровнен по центру.

## [1.7.1] — 2026-11-13

### Исправлено
- При привязке VK телефон из профиля теперь записывается в аккаунт (в `billing_phone`),
  если у аккаунта номера ещё нет и он не занят другим пользователем. E-mail — по тому же правилу.
- То же правило работает при создании аккаунта через VK.

## [1.7.0] — 2026-11-13

### Добавлено
- Привязка Telegram к существующему аккаунту: в личном кабинете рядом с Telegram
  показывается виджет с одноразовым токеном (10 минут), привязка принимается только
  в том аккаунте, из которого открыта.
- Разделитель «или» собран из двух линий и текста по центру — больше не зависит от
  псевдоэлементов и тем оформления.

## [1.6.1] — 2026-11-13

### Исправлено
- После привязки сервиса из личного кабинета пользователь возвращается в кабинет,
  а не в админ-профиль; там же показывается уведомление об успешной привязке.

## [1.6.0] — 2026-11-13

### Изменено
- На форме входа и регистрации соцкнопки перенесены под форму, отделены разделителем «или»
  и сгруппированы заголовком «Войти другим способом».
- Если скрипт Telegram не загрузился (сеть блокирует telegram.org), вместо пустого места
  показывается пояснение: «Вход через Telegram недоступен в вашей сети — используйте СМС-код или VK ID».

### Добавлено
- Блок «Способы входа» с привязкой VK ID теперь есть и в личном кабинете WooCommerce
  (главная страница аккаунта и «Данные аккаунта»), а не только в админке.
- Шорткод `[wp_smsn1_ru_login_methods]` для вывода блока в любом месте сайта.

## [1.5.0] — 2026-11-12

### Изменено
- Формы переведены на универсальную вёрстку: цвета и радиус в CSS-переменных
  (`--wp-smsn1-ru-accent`, `--wp-smsn1-ru-radius`), адаптив для узких экранов,
  кнопки в две колонки с переносом, отдельные классы для полей и действий.
- Улучшена доступность: у полей есть `label for`, `autocomplete`, `inputmode`,
  видимый `:focus`, уведомления с `role="status"` и `aria-live`.
- Оформление больше не зависит от `!important` и инлайновых стилей — тему проще переопределить.
- Поле кода и кнопки управляются классами (`is-ready`, `is-busy`), а не цветами в JS.

### Исправлено
- Опечатки: «Зарегестрироваться» → «Зарегистрироваться», «зарегестрирован» → «зарегистрирован»,
  «перенапрвлять» → «перенаправлять», «региcтрации» → «регистрации».
- В форме регистрации поле e-mail и пароля получили подписи-подсказки.
- Заглушка при недоступном сервисе СМС: понятный текст и кнопка стандартного входа.
- Перед редиректом после входа поддержан абсолютный URL (раньше ломался, если в настройке указан полный адрес).

## [1.4.0] — 2026-11-08

### Добавлено
- Вход через **Telegram** (Login Widget): кнопка на формах входа и регистрации.
- Проверка подписи: `HMAC-SHA256` с ключом `SHA256(bot_token)`, сравнение через `hash_equals`,
  контроль свежести `auth_date` (15 минут, настраивается фильтром `wp_smsn1_ru_telegram_max_age`).
- Настройки Telegram: включение, username бота, токен, домен для `/setdomain`.
- Callback виджетного входа: `/wp-smsn1-ru-oauth/telegram/` (rewrite-правило).
- Аккаунт из Telegram создаётся без e-mail (Telegram его не отдаёт), в профиле показывается
  подсказка добавить адрес.

## [1.3.0] — 2026-11-07

### Добавлено
- Каркас входа через внешние провайдеры: интерфейс `WP_SMSN1_RU_Auth_Provider`, реестр
  и фильтр `wp_smsn1_ru_auth_providers` (следом добавляются Telegram и MAX).
- VK ID (OAuth 2.1 + PKCE): редирект, обмен кода, профиль, вход и создание аккаунта.
- Раздел настроек «Способы входа»: включение VK ID, ID приложения, защищённый ключ
  и готовый Redirect URI для копирования в кабинет VK.
- Кнопки «Войти через …» на формах входа и регистрации.
- Привязка VK ID к существующему аккаунту из профиля (вручную); автомерж по e-mail запрещён.
- PKCE-утилиты (verifier, S256 challenge, device_id) с тестом на векторе RFC 7636.

## [1.2.0] — 2026-11-06

### Добавлено
- Режим входа «Пароль + OTP» (2FA): переключатель в настройках плагина, поле пароля в формах
  входа, проверка пароля до расхода кода, лимит 5 попыток пароля за 15 минут.
- Пользователи, созданные в режиме «только OTP», задают пароль при первом входе в режиме 2FA —
  он сохраняется после подтверждения кода (без блокировки входа).
- Форма регистрации в режиме 2FA спрашивает пароль и его подтверждение.
- Метка `wp_smsn1_ru_password_set` обновляется при смене пароля в профиле и при сбросе пароля.

## [1.1.0] — 2026-11-06

### Безопасность
- API переведён с HTTP на HTTPS: `wp_remote_get`, таймауты, проверка сертификата.
  HTTP-фолбэк возможен только явно — константой `WP_SMSN1_RU_ALLOW_HTTP_FALLBACK`.
- Подпись запросов вынесена в фильтр `wp_smsn1_ru_signature` (алгоритм задан протоколом провайдера).
- OTP: 5 цифр вместо 4, срок жизни кода — 90 секунд, не более 5 неверных попыток на код,
  после лимита код аннулируется.
- Ограничение отправки: пауза 60 с, 3 кода на номер за 20 минут, 10 кодов на IP за 20 минут (настраивается фильтрами).
- Текст СМС больше не подставляет заголовок Host (убрана инъекция через `HTTP_HOST`).
- Код хранится в транзиенте под хэшем номера, а не в имени с самим номером.

### Исправлено
- Вход по OTP вызывает `do_action('wp_login')` и `wp_set_current_user()` — работают 2FA и WooCommerce.
- Ошибки `wp_create_user()` больше не теряются, коллизия логина обрабатывается суффиксом.
- Баланс: текст ошибки приведён к ожидаемому значению — уведомления в админке снова показываются.
- WooCommerce: подтверждение номера не блокирует оформление заказа авторизованным покупателям.
- Некорректный ответ API больше не вызывает предупреждений PHP.
